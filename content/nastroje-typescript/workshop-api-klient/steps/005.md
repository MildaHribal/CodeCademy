# --description--

Teď máme v kódu duplicitu: `interface Station` i `stationSchema` popisují úplně to samé. Když přidáme do API nový atribut, budeme ho muset měnit na dvou místech.

To je zbytečné. Zod nám umí typ vyrobit rovnou ze schématu.

**Úkol:** Smaž `interface Station` a nahraď ho za typ vytvořený pomocí `z.infer`. Následná proměnná `example: Station` tím zůstane platná a ověří, že to funguje správně.

# --hints--

`index.ts` prochází kontrolou typů bez chyb.

```js
const result = await helpers.run('npx tsc --noEmit', { timeoutMs: 60000 });
assert.equal(result.code, 0, `tsc má projít bez chyb, ale vypsal:\n${result.stdout}`);
```

Starý `interface Station` je smazaný.

```js
assert.ok(!files['index.ts'].includes('interface Station {'), 'Musíš smazat starý interface Station.');
```

Typ `Station` je odvozený ze `stationSchema`.

```js
assert.match(files['index.ts'], /type\s+Station\s*=\s*z\.infer\s*<\s*typeof\s+stationSchema\s*>/, 'Typ Station má být odvozený pomocí z.infer<typeof stationSchema>');
```

import { z } from 'zod';
type Station = z.infer<typeof stationSchema>;

const example: Station = {
  id: "s1",
  name: "Hlavní nádraží",
  bikesAvailable: 5,
  isRenting: true
};

// Zde definuj stationSchema
const stationSchema = z.object({
  id: z.string(),
  name: z.string(),
  bikesAvailable: z.number(),
  isRenting: z.boolean(),
});

// 2. Vytvoř funkci getStations
export async function getStations() {
  const response = await fetch('https://api.example.com/stations');
  const data: unknown = await response.json();
  return data;
}
