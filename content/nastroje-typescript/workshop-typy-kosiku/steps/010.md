# --description--

Ke každému stavu patří věta pro zákazníka. Nabízí se objekt `POPISY_STAVU`,
kde klíč je stav a hodnota text. Chceš dvě věci najednou: aby kontrola hlídala,
že máš popis ke **každému** stavu a jiné klíče tam nejsou — a zároveň aby si
TypeScript pamatoval, jaký text v kterém klíči je.

Anotace dvojtečkou umí jen to první. Proměnná se pak tváří přesně jako napsaný
typ a přesné texty se zapomenou. Proto existuje `satisfies`: **zkontroluj to
proti typu, ale typ hodnoty mi nepřepisuj.** A aby si texty zůstaly texty,
připoj k nim ještě `as const` z minulého kroku — v moderním kódu tenhle pár
uvidíš často.

**Úkol:** v `katalog.ts` přidej a vyexportuj `POPISY_STAVU` s popisem ke každému
ze tří stavů (texty si vymysli, uvidí je zákazník). Zapiš ho tak, aby si
TypeScript zapamatoval přesné texty a zároveň ověřil, že sedí na typ
`Record<Stav, string>`.

`Record<Klic, Hodnota>` je hotový typ pro slovník: klíče typu `Klic`, hodnoty
typu `Hodnota`. Víc takových pomocných typů je v lekci
[Zúžení typů a generika](see:nastroje-typescript/zuzovani-a-genericita), teď
stačí vědět, že `Record<Stav, string>` znamená „ke každému stavu jeden text".

# --explain--

Vysvětli vlastními slovy, proč se u `POPISY_STAVU` hodí `satisfies` a ne anotace
dvojtečkou, když obě kontroly zdánlivě dělají totéž.

## --model--

Anotace dvojtečkou říká „tahle proměnná **je** tenhle typ" — TypeScript od té
chvíle o hodnotě ví jen to, co je v typu, a co jsem do ní napsal, zapomene.
`satisfies` říká „zkontroluj, že hodnota **odpovídá** tomuhle typu, ale její
vlastní typ mi nech". Dostanu tak obojí: kontrolu, že mi žádný stav nechybí
a žádný přebývá, i hodnotu, o které se dá dál odvozovat.

## --checklist--

- Anotace dvojtečkou přepíše typ hodnoty na ten napsaný.
- `satisfies` typ hodnoty nemění, jen ho ověří proti napsanému typu.
- Obojí zachytí chybějící i přebývající klíč.
- Přesné texty udrží `as const`; se `satisfies` jde dohromady, s anotací ne.

# --help--

## --tip--

Hledáš klíčové slovo, které se píše **za** hodnotu a chová se jako kontrola
„odpovídá tomuhle typu?". Před ním ještě zůstane `as const` z minulého kroku.

## --tip--

Klíč `'na-objednavku'` obsahuje pomlčku, takže ho v objektu musíš napsat
v uvozovkách. Ostatní dva klíče uvozovky nepotřebují.

## --tip--

Stejný vzor na jiných datech:
`const ZKRATKY = { maly: 'S', velky: 'XL' } as const satisfies Record<Velikost, string>;`

## --file-- kosik.ts

```ts
import { katalog } from './katalog.ts';
import type { Hra } from './katalog.ts';

export type Polozka = {
  hra: Hra;
  kusy: number;
};

// Najde hru v katalogu podle id. Když taková není, vrátí undefined.
export function najdiHru(id: number) {
  return katalog.find((hra) => hra.id === id);
}

export function mezisoucet(kosik: Polozka[]): number {
  return kosik.reduce((soucet, polozka) => soucet + polozka.hra.cena * polozka.kusy, 0);
}

export function pridej(kosik: Polozka[], hra: Hra, kusy: number): Polozka[] {
  const uzTam = kosik.some((polozka) => polozka.hra.id === hra.id);
  if (uzTam) {
    return kosik.map((polozka) =>
      polozka.hra.id === hra.id ? { ...polozka, kusy: polozka.kusy + kusy } : polozka,
    );
  }
  return [...kosik, { hra, kusy }];
}

export function nazevHry(hra: Hra): string {
  return hra.podtitul ? `${hra.nazev}: ${hra.podtitul}` : hra.nazev;
}
```
