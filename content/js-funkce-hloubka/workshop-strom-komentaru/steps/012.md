# --description--

Smazaný komentář, pod kterým nikdo neodpověděl, nemá smysl ukazovat vůbec — jako spam pod receptem. Pozor na řetěz: smazaný komentář, jehož jediná odpověď je taky smazaná a bez odpovědí, po vyčištění **žádné odpovědi nemá**, takže zmizí taky.

**Úkol:** Napiš funkci `pruneDeleted(nodes)`, která vrátí nový strom bez smazaných uzlů, které po vyčištění nemají žádné odpovědi. Smazané uzly s odpověďmi zůstanou. Vstupní strom se nezmění.

Vyzkoušej ji na stromu z minulých kroků: vypiš si odsazené řádky `pruneDeleted(maskDeleted(threadFromApi(comments)))` a sleduj, že spam pod receptem zmizel.

Kandidáti: `map` a `filter` v tom správném pořadí, nebo `for…of` s `push`. Rozhoduje, jestli se o uzlu rozhoduješ **před**, nebo **po** vyčištění jeho odpovědí.

# --hints--

Smazaný uzel bez odpovědí zmizí, smazaný uzel s odpovědí zůstane.

```js
const tree = [
  { id: 1, deleted: true, replies: [] },
  { id: 2, deleted: true, replies: [{ id: 3, deleted: false, replies: [] }] },
  { id: 4, deleted: false, replies: [] },
];
assert.deepEqual(pruneDeleted(tree).map((node) => node.id), [2, 4], 'pruneDeleted má odstranit smazaný uzel 1 bez odpovědí a nechat 2 (má odpověď) a 4');
```

Smazaný uzel, jehož odpovědi po vyčištění zmizely, zmizí taky — i hluboko ve stromu.

```js
const tree = [
  { id: 1, deleted: false, replies: [
    { id: 2, deleted: true, replies: [{ id: 3, deleted: true, replies: [] }] },
    { id: 4, deleted: false, replies: [] },
  ] },
];
const result = pruneDeleted(tree);
assert.deepEqual(result[0].replies.map((node) => node.id), [4], 'pod uzlem 1 má zůstat jen 4 — smazaný 2 měl jen smazanou odpověď 3 bez odpovědí');
```

Vstupní strom zůstane beze změny.

```js
const tree = [{ id: 1, deleted: false, replies: [{ id: 2, deleted: true, replies: [] }] }];
pruneDeleted(tree);
assert.equal(tree[0].replies.length, 1, 'pruneDeleted nesmí odebrat odpověď z původního stromu');
```

# --help--

## --tip-- 1

Nejdřív vyřeš podstrom, pak rozhoduj o rodiči — stejně jako `countProducts` v části [Rekurze a zásobník volání](see:js-funkce-hloubka/funkcionalni-styl#rekurze-a-zasobnik-volani) potřebuje výsledky podkategorií, než vrátí svůj.

## --tip-- 2

Pro každý uzel nejdřív vyrob kopii s vyčištěnými odpověďmi a teprve nad kopiemi rozhodni, které uzly zůstanou. Když rozhodneš podle původních `replies`, řetěz smazaných komentářů přežije.

# --explain--

Vysvětli vlastními slovy, proč musí `pruneDeleted` vyčistit odpovědi uzlu **dřív**, než rozhodne, jestli uzel zůstane.

## --model--

O smazaném uzlu se rozhoduje podle toho, jestli má nějaké odpovědi. Jenže jeho odpovědi můžou být taky smazané a bez odpovědí, takže po vyčištění zmizí. Když funkce nejdřív rekurzivně vyčistí podstrom a teprve pak se podívá na počet odpovědí, vidí skutečný stav a řetěz prázdných smazaných komentářů odstraní celý. Kdyby rozhodovala podle původních odpovědí, smazaný rodič by zůstal viset bez obsahu.

## --checklist--

- Smazaný uzel zůstává jen tehdy, když má odpovědi.
- Odpovědi můžou po vyčištění zmizet.
- Funkce proto nejdřív rekurzivně zpracuje podstrom.
- Teprve podle vyčištěných odpovědí rozhodne o uzlu.
