# --description--

Tady máš hotové schéma, klidně si dej pauzu. Od teď píšeš dotazy.

Stránka podniku ukazuje recenze se jménem autora. V `reviews` je ale jen `user_id` a jméno
je v tabulce `users`. Dva dotazy a skládání v JavaScriptu nejsou potřeba: `JOIN` spojí řádky
dvou tabulek podle podmínky za `ON`.

```sql
SELECT orders.id, customers.name AS customer, orders.total
FROM orders
JOIN customers ON customers.id = orders.customer_id
WHERE orders.total > ?
ORDER BY orders.created_at DESC;
```

Databáze ke každé objednávce najde zákazníka, jehož `id` se rovná `customer_id`, a z dvojice
udělá jeden řádek výsledku. Protože obě tabulky mají sloupec `id`, píšou se sloupce **s jménem
tabulky** (`orders.id`), jinak dotaz skončí chybou `ambiguous column name: id`. `AS customer`
dá sloupci ve výsledku jméno, pod kterým ho najdeš v objektu.

**Úkol:** napiš a vyexportuj `reviewsForRestaurant(db, restaurantId)`. Vrátí recenze daného
podniku jako objekty s klíči `author` (jméno uživatele), `rating` a `comment`, od nejnovější.

# --explain--

Vysvětli vlastními slovy, co udělá `JOIN users ON users.id = reviews.user_id` a proč je výsledek lepší než načíst recenze a pak pro každou zvlášť dohledat jméno autora.

## --model--

`JOIN` vezme každou recenzi a najde k ní řádek v `users`, jehož `id` se rovná `user_id`
recenze. Z dvojice udělá jeden řádek, takže ve výsledku mám sloupce z obou tabulek. Všechno
spojí databáze v jednom dotazu. Dohledávání jména pro každou recenzi zvlášť by znamenalo
tolik dalších dotazů, kolik je recenzí.

## --checklist--

- `JOIN` spojí řádky dvou tabulek podle podmínky za `ON`.
- Podmínka porovnává cizí klíč s primárním klíčem druhé tabulky.
- Výsledek má sloupce z obou tabulek v jednom řádku.
- Jeden dotaz nahradí dotaz na autora pro každou recenzi zvlášť.

```sql
CREATE TABLE restaurants (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  city TEXT NOT NULL,
  cuisine TEXT NOT NULL,
  price_level INTEGER NOT NULL CHECK (price_level BETWEEN 1 AND 3)
) STRICT;

CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  email TEXT NOT NULL UNIQUE
) STRICT;

CREATE TABLE reviews (
  id INTEGER PRIMARY KEY,
  restaurant_id INTEGER NOT NULL REFERENCES restaurants (id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users (id),
  rating INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
  comment TEXT NOT NULL,
  created_at TEXT NOT NULL,
  UNIQUE (restaurant_id, user_id)
) STRICT;
```

## --file-- db.js

```js
import { readFileSync } from 'node:fs';
import { DatabaseSync } from 'node:sqlite';

const read = (name) => readFileSync(new URL(name, import.meta.url), 'utf8');

// Založí databázi v paměti: schéma, podniky a uživatele.
// Recenze z reviews.sql nahraje, jakmile ve schématu existuje tabulka reviews.
export function openDb() {
  const db = new DatabaseSync(':memory:');
  db.exec(read('./schema.sql'));
  db.exec(read('./data.sql'));
  const hasReviews = db
    .prepare("SELECT 1 FROM sqlite_schema WHERE type = 'table' AND name = 'reviews'")
    .get();
  if (hasReviews) db.exec(read('./reviews.sql'));
  return db;
}
```

## --file-- queries.js

```js
// Dotazy nad recenzemi podniků. Každá funkce dostane otevřenou databázi db.

export function restaurantsInCity(db, city) {
  return db.prepare('SELECT name, cuisine FROM restaurants WHERE city = ? ORDER BY name').all(city);
}

export function reviewsForRestaurant(db, restaurantId) {
  return db
    .prepare(`
      SELECT users.name AS author, reviews.rating, reviews.comment
      FROM reviews
      JOIN users ON users.id = reviews.user_id
      WHERE reviews.restaurant_id = ?
      ORDER BY reviews.created_at DESC
    `)
    .all(restaurantId);
}
```
