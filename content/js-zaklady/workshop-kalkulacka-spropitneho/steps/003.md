# --description--

Mezisoučet je cena všech jídel bez spropitného: cena polévky krát počet polévek, plus totéž pro hlavní jídla a nápoje.

**Úkol:** Pod výpis počtu položek založ konstantu `subtotal` a spočítej ji **jedním výrazem** z šesti proměnných nahoře. Pak ji vypiš s popiskem, třeba `Mezisoučet: 1115 Kč`.

Závorky nepotřebuješ: násobení má přednost před sčítáním, takže se nejdřív spočítají tři součiny a pak se sečtou. Stejný tvar na jiných datech — vstupenky do kina:

```js
const ticketsTotal = adultPrice * adults + childPrice * children;
console.log('Vstupenky:', ticketsTotal, 'Kč');
```

# --hints--

`subtotal` je `1115`.

```js
assert.equal(subtotal, 1115, 'subtotal má být 1115 (89 × 2 + 239 × 3 + 55 × 4)');
```

`subtotal` se počítá z cen a počtů, pro jinou cenu hlavního jídla vyjde jinak.

```js

  return new Function(`${src}\nreturn { ${names} };`)();

assert.equal(other.subtotal, 995, 'S cenou hlavního jídla 199 Kč má subtotal vyjít 995 — počítáš z proměnných?');
```

Mezisoučet je vypsaný v konzoli.

```js
assert.ok(logs.some((line) => line.text.includes('1115')), 'V konzoli má být řádek s mezisoučtem (1115)');
```

# --explain--

Vysvětli vlastními slovy, proč výraz `soupPrice * soups + mainPrice * mains + drinkPrice * drinks` spočítá mezisoučet správně bez závorek, a kdy by závorky potřeboval.

## --model--

Násobení má přednost před sčítáním, takže JavaScript nejdřív spočítá tři součiny cena krát počet a teprve ty sečte — přesně jak to mezisoučet potřebuje. Závorky bych potřeboval, kdybych chtěl opačné pořadí, třeba nejdřív sečíst počty a pak násobit, nebo nejdřív sečíst ceny a výsledek vydělit počtem lidí. Když si pořadím nejsem jistý, závorky přidám kvůli čitelnosti.

## --checklist--

- Násobení a dělení mají přednost před sčítáním a odčítáním.
- Tři součiny se spočítají dřív, než se sečtou.
- Závorky změní pořadí, když má sčítání proběhnout dřív.
- Závorky se hodí i pro čitelnost, když pořadí není na první pohled jasné.
