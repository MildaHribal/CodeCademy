# --description--

## Hlášení

Kolegyně stylovala poznámku „Vstupenka je na jméno…" a napsala: „Chtěla jsem, aby poznámka byla přes celou kartu a od obou stran odsazená o 1rem. Vlevo odsazená je, ale vpravo přečnívá skoro až k rámečku karty. Na telefonu je to ještě vidět víc."

Čekali jsme světle oranžový proužek s mezerou 16 px vlevo i vpravo od textu karty. Ve skutečnosti je proužek posunutý o 16 px doprava a o 16 px širší, než by měl.

## Úkol

Najdi, proč pravý margin poznámky nefunguje, a oprav pravidlo `.ticket__note`. Změň co nejmenší kus kódu.

# --hints--

Poznámka má 16 px mezeru od obsahu karty vlevo i vpravo.

```js
document.querySelectorAll('.ticket').forEach((ticket, i) => {
  const style = getComputedStyle(ticket);
  const box = ticket.getBoundingClientRect();
  const contentLeft = box.left + parseFloat(style.borderLeftWidth) + parseFloat(style.paddingLeft);
  const contentRight = box.right - parseFloat(style.borderRightWidth) - parseFloat(style.paddingRight);
  const note = ticket.querySelector('.ticket__note').getBoundingClientRect();
  assert.ok(Math.abs(note.left - contentLeft - 16) <= 1, `Karta ${i + 1}: poznámka začíná ${Math.round(note.left - contentLeft)} px od obsahu karty, čekám 16 px`);
  assert.ok(Math.abs(contentRight - note.right - 16) <= 1, `Karta ${i + 1}: poznámka končí ${Math.round(contentRight - note.right)} px před koncem obsahu karty, čekám 16 px`);
});
```

Na šířce 375 px poznámka nepřečnívá přes obsah karty.

```js
await helpers.resize(375);
document.querySelectorAll('.ticket').forEach((ticket, i) => {
  const style = getComputedStyle(ticket);
  const contentRight = ticket.getBoundingClientRect().right - parseFloat(style.borderRightWidth) - parseFloat(style.paddingRight);
  const note = ticket.querySelector('.ticket__note').getBoundingClientRect();
  assert.ok(note.right <= contentRight + 1, `Při šířce 375 px končí poznámka v kartě ${i + 1} na ${Math.round(note.right)} px, obsah karty na ${Math.round(contentRight)} px`);
});
```

Poznámka má dál svůj vzhled: vnitřní odsazení a mezeru nad a pod sebou 16 px.

```js
const style = getComputedStyle(document.querySelector('.ticket__note'));
assert.equal(style.marginTop, '16px', 'Poznámka má mít dál marginTop 16px');
assert.equal(style.marginBottom, '16px', 'Poznámka má mít dál marginBottom 16px');
assert.equal(style.paddingLeft, '12px', 'Poznámka má mít dál paddingLeft 12px');
```

# --help--

## --tip--

Poznámka je blok s pevnou šířkou a marginem po stranách. Přesně tuhle situaci ukazuje předpověď v části [width: auto není totéž co width: 100%](see:css-box-model/box-model#width-auto-neni-totez-co-width-100).

## --tip--

Otevři v DevTools panel Computed u poznámky a porovnej šířku poznámky se šířkou obsahu karty. Která deklarace v `.ticket__note` šířku natvrdo určuje?

# --explain--

Vysvětli vlastními slovy, proč poznámka s `width: 100%` a `margin-inline: 1rem` přečnívala a proč pomohlo šířku nenastavovat.

## --model--

`width: 100%` nastaví poznámce šířku celého obsahu karty. Levý margin ji k tomu odsune o 16 px doprava, takže na pravý margin už místo nezbude a poznámka přečnívá. Výchozí `width: auto` u bloku vyplní šířku rodiče až po odečtení marginu, rámečku i paddingu, takže mezera je pak na obou stranách.

## --checklist--

- `width: 100%` dá boxu celou šířku obsahu rodiče.
- Margin se k pevné šířce přidá zvenku, takže box přeteče.
- `width: auto` u bloku odečte margin od šířky rodiče sama.
- Blokový prvek, který má vyplnit rodiče, šířku nepotřebuje.
