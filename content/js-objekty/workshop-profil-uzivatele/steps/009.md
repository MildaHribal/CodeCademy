# --description--

Město je o patro níž, v objektu `location`. Tady se mutuje omylem nejčastěji.

> [!PITFALL]
> `const copy = { ...profile }; copy.location.city = city;` vypadá jako práce s kopií. Jenže spread zkopíroval jen **první patro** — `copy.location` je tentýž objekt jako `profile.location`, a město se změní i v uloženém profilu.

**Úkol:** Napiš funkci `withCity(profile, city)`, která vrátí nový profil s novým městem. Nový musí být vnější objekt i objekt `location`; `remote` zůstane, jak byl, a původní profil se nezmění.

Kandidáti: jeden spread (nestačí), spread s novým objektem `location` uvnitř, nebo mutace kopie (rozbije originál). Vzor na jiných datech — objednávka s novým PSČ:

```js
const moved = { ...order, address: { ...order.address, zip: '602 00' } };
```

# --hints--

`withCity` vrátí profil s novým městem a zachová `remote`.

```js
const result = withCity(savedProfile, 'Ostrava');
assert.deepEqual(result.location, { city: 'Ostrava', remote: true }, "withCity(savedProfile, 'Ostrava').location má být { city: 'Ostrava', remote: true }");
assert.equal(result.fullName, 'Jana Dvořáková', 'withCity má zachovat ostatní údaje profilu');
```

Uložený profil ani jeho `location` se nezmění.

```js
const originalLocation = savedProfile.location;
const result = withCity(savedProfile, 'Ostrava');
assert.equal(savedProfile.location.city, 'Brno', "po withCity(savedProfile, 'Ostrava') má mít savedProfile.location.city pořád 'Brno'");
assert.equal(savedProfile.location, originalLocation, 'withCity nesmí do savedProfile přiřadit jiný objekt location');
assert.notEqual(result.location, savedProfile.location, 'výsledek withCity má mít nový objekt location, ne ten z uloženého profilu');
assert.notEqual(result, savedProfile, 'withCity má vrátit nový profil');
```

# --help--

## --tip--

Jde o úpravu o patro níž — viz past [Spread kopíruje jen první patro](see:js-objekty/reference-a-mutace#spread-kopiruje-jen-prvni-patro).

## --tip--

Nový objekt potřebuješ v každém patře cesty k městu: vnější profil a v něm vlastnost `location` s novým objektem, do kterého rozprostřeš původní `location` a přepíšeš `city`.

## --tip--

Na jiných datech: nový tým s novým trenérem na hřišti je `{ ...team, coach: { ...team.coach, name: 'Radka' } }`.

# --explain--

Vysvětli vlastními slovy, proč `{ ...profile }` nestačí na změnu města a co musí být u `withCity` nové.

## --model--

Spread kopíruje jen první patro: nový je vnější objekt, ale ve vlastnosti `location` je pořád odkaz na původní objekt adresy. Zápis do `copy.location.city` by proto změnil i uložený profil. Musím vytvořit nový objekt v každém patře, kterým k městu jdu: nový profil a v něm nový `location` s rozprostřenými původními údaji a novým městem. Ostatní části, třeba `links`, se nemění, takže můžou zůstat sdílené.

## --checklist--

- Spread vytvoří nový jen vnější objekt.
- Vnořený objekt zůstane v kopii tentýž jako v originálu.
- Nový objekt je potřeba v každém patře cesty ke změněnému údaji.
- Části, které se nemění, můžou zůstat sdílené.
