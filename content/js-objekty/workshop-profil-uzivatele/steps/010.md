# --description--

## Hlášení

Stránka **Soukromí** má náhled: uživatelka zapne „Ukázat e-mail", podívá se, jak bude profil vypadat, a klikne na **Zrušit**. Náhled počítá kolegova funkce `updatePrivacy(profile, changes)` z horní části souboru.

Po zrušení ale uložený profil `savedProfile` má `privacy.showEmail: true` taky — e-mail je najednou veřejný, i když nic neuložila. Kolega tvrdí, že funkce přece vrací nový objekt přes spread. V konzoli žádná chyba není.

## Úkol

Oprav `updatePrivacy` tak, aby vracela profil s novým nastavením soukromí a původní profil ani jeho `privacy` neměnila. Změň co nejmenší kus kódu.

# --hints--

`updatePrivacy` vrátí profil se změněným nastavením soukromí.

```js
const result = updatePrivacy(savedProfile, { showEmail: true });
assert.deepEqual(result.privacy, { showEmail: true, showCity: true }, 'updatePrivacy(savedProfile, { showEmail: true }).privacy má být { showEmail: true, showCity: true }');
```

Uložený profil a jeho `privacy` se nezmění.

```js
const result = updatePrivacy(savedProfile, { showEmail: true, showCity: false });
assert.deepEqual(savedProfile.privacy, { showEmail: false, showCity: true }, 'po updatePrivacy má mít savedProfile.privacy pořád { showEmail: false, showCity: true }');
assert.notEqual(result.privacy, savedProfile.privacy, 'výsledek updatePrivacy má mít nový objekt privacy');
```

Ostatní funkce fungují dál.

```js
assert.equal(withCity(savedProfile, 'Zlín').location.city, 'Zlín', "withCity(savedProfile, 'Zlín') má dál fungovat");
assert.equal(updateProfile(savedProfile, { id: 1 }).id, 481, 'updateProfile má dál chránit id');
```

# --help--

## --tip--

Chyba odpovídá pasti [„Kopie“ přiřazením](see:js-objekty/reference-a-mutace#kopie-prirazenim), jen o patro níž.

## --tip--

Na co ukazuje proměnná `privacy` na druhém řádku funkce? Do kterého objektu pak cyklus zapisuje?

## --tip--

Na jiných datech: `const address = { ...order.address };` vytvoří novou adresu, do které můžeš zapisovat bez zásahu do objednávky.

# --explain--

Vysvětli vlastními slovy, proč kolegova funkce měnila uložený profil, přestože vracela nový objekt přes spread.

## --model--

`const privacy = profile.privacy` nevytvořila kopii, jen druhý odkaz na objekt soukromí uloženého profilu. Cyklus pak zapisoval do toho sdíleného objektu, takže se změnil i originál. Spread na konci vytvořil nový vnější profil, ale do něj dal odkaz na už zmutovaný objekt. Oprava je udělat nejdřív kopii `{ ...profile.privacy }` a zapisovat až do ní.

## --checklist--

- Přiřazení vnořeného objektu do proměnné zkopíruje jen odkaz.
- Zápis přes ten odkaz mění objekt uloženého profilu.
- Nový vnější objekt ze spreadu nepomůže, když je vnořený objekt už zmutovaný.
- Do vnořeného objektu se smí zapisovat až po vytvoření jeho kopie.
