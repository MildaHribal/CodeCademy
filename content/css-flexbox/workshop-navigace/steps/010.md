# --description--

Na úzké obrazovce leží tlačítko „Objednat" až pod navigací. Chceme logo a tlačítko nahoře vedle sebe a navigaci pod nimi.

Vlastnost `order` mění **vizuální pořadí** flex položek. Všechny položky mají výchozí `order: 0`. Prohlížeč je seřadí vzestupně podle `order` a při shodě podle pořadí v HTML. Položka s `order: 1` se proto postaví za všechny ostatní.

**Úkol:** do pravidla `.main-nav` v media dotazu přidej `order: 1`. HTML neměň. Výsledek uvidíš jen v zúženém náhledu, stejně jako v minulém kroku.

### Proč s `order` opatrně

`order` mění jen to, co je vidět. Čtečka obrazovky i klávesa Tab jdou pořád **v pořadí HTML**. Když se vizuální pořadí a pořadí v kódu rozejdou, člověk ovládající stránku klávesnicí vidí, jak mu fokus skáče po obrazovce sem a tam, a nevyzná se v tom.

Tady je to přijatelné: změna platí jen na úzké obrazovce a skok je malý (Tab jde z loga na navigaci pod ním a pak zpátky nahoru na tlačítko). Rozumné pravidlo zní:

- `order` použij na drobné přeskupení, u kterého pořadí nemění smysl obsahu,
- když se má pořadí změnit doopravdy (a na všech šířkách), přesuň prvky v HTML.

Příklad na jiných datech — na úzké obrazovce přesuneš obrázek článku nad nadpis, přičemž v HTML je nadpis první (a čtečka ho tak přečte jako první, což dává smysl):

```css
@media (max-width: 40rem) {
  .article__image {
    order: -1;
  }
}
```

# --hints--

Při šířce stránky 560 px stojí logo a tlačítko vedle sebe v prvním řádku, tlačítko u pravého okraje.

```js
await helpers.resize(560);
const header = document.querySelector('.site-header');
const contentRight = header.getBoundingClientRect().right - parseFloat(getComputedStyle(header).paddingRight);
const logo = document.querySelector('.logo').getBoundingClientRect();
const button = document.querySelector('.button').getBoundingClientRect();
assert.ok(button.top < logo.bottom && button.bottom > logo.top, 'Tlačítko má být ve stejném řádku jako logo');
assert.ok(Math.abs(button.right - contentRight) <= 1, 'Tlačítko má být u pravého okraje hlavičky');
```

Při šířce stránky 560 px je navigace pod logem i tlačítkem.

```js
await helpers.resize(560);
const nav = document.querySelector('.main-nav').getBoundingClientRect();
const logo = document.querySelector('.logo').getBoundingClientRect();
const button = document.querySelector('.button').getBoundingClientRect();
assert.ok(nav.top >= logo.bottom && nav.top >= button.bottom, 'Navigace má být až pod logem a tlačítkem');
```

Při šířce stránky 1024 px je pořadí pořád logo, navigace, tlačítko.

```js
const logo = document.querySelector('.logo').getBoundingClientRect();
const nav = document.querySelector('.main-nav').getBoundingClientRect();
const button = document.querySelector('.button').getBoundingClientRect();
assert.ok(nav.left > logo.right && button.left > nav.right, 'Na široké obrazovce se pořadí nemá měnit');
```

V HTML zůstává pořadí logo, navigace, tlačítko — pro čtečky obrazovky a klávesu Tab.

```js
const children = [...document.querySelector('.site-header').children];
const position = (selector) => children.findIndex((el) => el.matches(selector));
assert.ok(position('.logo') < position('.main-nav') && position('.main-nav') < position('.button'), 'Pořadí prvků v HTML hlavičky se změnilo');
```
